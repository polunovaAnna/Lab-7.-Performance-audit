## Умови вимірювання

- Машина: ASUS Vivobook (X1403ZA), Intel Core i5-12500H, 8 Гб ОЗП
- ОС: Windows (11 Home Single Language), версія 26H2
- Живлення: від батареї
- Браузер: Google Chrome 157.0.8103.79, вікно інкогніто
- Збірка: `npm run build` + `npm run preview` (http://localhost:4173), Node (v24.15.0)
- Завантаження (Lighthouse): режим Navigation, Mobile, стандартний (simulated) throttling Lighthouse
- Взаємодії (DevTools Performance, Live metrics): CPU 4× slowdown, Network Fast 4G, Disable cache
- Перед кожним запуском сторінка перезавантажується, один запуск = один сценарій

## Виправлення

### Виправлення 1: Застосування content-visibility для пропуску рендеру позаекранних карток

- Сценарій: Завантаження сторінки
- Що змінено: До класу _.tutor-card_ додано _content-visibility: auto_ та стабільну висоту-заглушку _contain-intrinsic-size_.

| Метрика    | До (медіана) | Після (медіана) | Зміна  |
| ---------- | ------------ | --------------- | ------ |
| Обсяг, KiB | 6014         | 2741            | -3273  |
| LCP, с     | 9,8          | 11,1            | +1,3   |
| TBT, мс    | 21810        | 10750           | -11060 |

- Причина: під час завантаження браузер рахував стилі й layout для всіх карток, навіть тих, що далеко за екраном. Це блокувало main thread і затримувало малювання. _content-visibility: auto_ каже браузеру пропустити цю роботу для карток поза екраном, поки до них не доскролять.
- Коміт: https://github.com/polunovaAnna/Lab-7.-Performance-audit/commit/3244741b731d8ecc8b7b30e6037bb9976a49c34f

### Виправлення 2: Мемоізація карток та стабілізація колбеків для пошуку

- Сценарій: Пошук (введення та видалення тексту)
- Що змінено: _TutorList_ і _TutorCard_ обгорнуто в _memo_. В _App.jsx_ колбеки обгорнуто в _useCallback_, inline-стиль винесено в константу. У _TutorList_ замість нової стрілки _() => onSelect(tutor.id)_ передається сам _onSelect_, а _tutor.id_ підставляє картка.

| Метрика       | До (медіана) | Після (медіана) |  Зміна   |
| :------------ | :----------: | :-------------: | :------: |
| INP введення  |   4120 мс    |     1896 мс     | -2224 мс |
| INP видалення |   7696 мс    |     6760 мс     | -936 мс  |

- Причина: на кожну літеру в пошуку змінюється список, і React заново рендерив усі картки, навіть ті, у яких нічого не змінилось. _memo_ пропускає рендер, якщо пропси такі самі, але inline-функції щоразу створювались заново, тож пропси завжди виглядали новими. Стабільні посилання разом із _memo_ дозволили пропускати незмінені картки.
- Коміт: https://github.com/polunovaAnna/Lab-7.-Performance-audit/commit/6b012cd39f2d5268b29b3b76f491a9b287dbcc2c, https://github.com/polunovaAnna/Lab-7.-Performance-audit/commit/da0c7ac8138dc940b3f979c2d108c7628d65229e

### Виправлення 3: Оптимізація роботи фільтрів

- Сценарій: Застосування фільтрів
- Що змінено: у _Filters.jsx_ підрахунок кількості репетиторів по предметах і побудову списку груп обгорнуто в _useMemo_. В _App.jsx_ список _visible_ теж обгорнуто в _useMemo_ із залежностями _[query, filters, sortBy]_.

| Метрика | До (медіана) | Після (медіана) |  Зміна  |
| :------ | :----------: | :-------------: | :-----: |
| INP     |   1584 мс    |     648 мс      | -936 мс |

- Причина: панель фільтрів на кожному рендері заново проходила по всіх репетиторах, щоб порахувати кількість по предметах, хоча самі дані не змінюються. Тепер підрахунок виконується один раз і перераховується лише коли зміниться список _tutors_.
- Коміт: https://github.com/polunovaAnna/Lab-7.-Performance-audit/commit/982e1016862c4fd76d70bf93b7db59def9b7f788

### Виправлення 4: Оптимізація медіаконтенту та зображень

- Сценарій: Завантаження сторінки
- Що змінено: PNG конвертовано у WebP, додано _loading="lazy"_ для фото карток, _width_ і _height_ для резервування місця.

| Метрика | До (медіана) | Після (медіана) | Зміна  |
| :------ | :----------: | :-------------: | :----: |
| Size kB |     604      |       7,5       | -596,5 |
| Час мс  |      54      |       31        |   23   |

- Причина: При ініціалізації додатку браузер намагався паралельно завантажити понад 30 PNG по ~600 КБ, що створювало критичне перевантаження мережі та затримувало появу основного контенту. Атрибут _loading="lazy"_ відклав завантаження позаекранних картинок, формат WebP зменшив загальний обсяг даних.
- Коміт: https://github.com/polunovaAnna/Lab-7.-Performance-audit/commit/495e63bcbf2a044f56012edacac70bba8a96c468, https://github.com/polunovaAnna/Lab-7.-Performance-audit/commit/0a1b2cfebaac02822c083588abc1715dcd75abe4
